## Sizes

`small` sets the value a step smaller; `size` sets it to any CSS length.

  <Stat value="3 to 9 in" />

## Colour and trend

`hue` colours the value in the hue's text-safe shade (a palette hue, or a hex code, which is used as
given). `trend` puts a small arrow beside it, in the text colour, with "up" or "down" read to screen
readers; it says nothing about good or bad.

<Demo label="A hue and a trend">
  <Stat value="62 %" hue="teal" trend="up" />
  <Stat value="4.5 m" hue="coral" trend="down" />
  <Stat value="1,204" hue="#a064d8" />
</Demo>

## Counting up

With `animate`, the number counts up from zero the first time it is well in view, over 1.2s on an
ease-out, then lands with the emphasis pop. `--rkui-stat-count-duration` sets the length. Without
`animate` a stat is static and just shows its value.

Every number in the value counts together, keeping its decimals, thousands commas and words: "3 to 9
in" counts both numbers, "4.5 m" counts to one decimal. A sign in front of a number stays put, so
"−3 °C" counts 0 to 3 behind its minus. The stat itself is still static; `stat-enhance.js` does the
counting, over a copy of the text that screen readers skip, in which each number keeps its final
width, so nothing moves and the real value is always what is read.

An animated stat already in view as the page loads counts too when the page inlines
`table-init.js` in `<head>` (the `rkui()` add-on does), which keeps it hidden until it starts;
without it, that stat shows its final value. With JavaScript off, or with reduced motion, every
stat shows its final value at once.
